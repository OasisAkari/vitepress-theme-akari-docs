# レイアウトとアプリバー

レイアウトは [m3.material.io](https://m3.material.io) に合わせています。アプリバーとサイドナビゲーションはウィンドウに固定され、コンテンツ、右側の目次、ページ送りカードは角の丸い 1 枚のドキュメントサーフェスに載ります。フッターはその下にある 2 枚目のサーフェスです。ページ全体をブラウザーのウィンドウがスクロールするため、ページ内検索、戻る・進む、アンカーへのジャンプはすべてブラウザーの通常の動作どおりに働きます。

## アプリバー

- **左側**：サイトのロゴ、名前、バージョン番号。記事のタイトルがアプリバーの下にスクロールすると、名前が現在のページのタイトルに変わります。狭い画面では、ナビゲーションドロワーを開くメニューボタンが左端に表示されます。
- **右側**：検索ボックス、ソーシャルリンク、設定ボタン。スペースが足りなくなると、検索ボックスは丸いボタンに縮み、ソーシャルリンクと設定は 3 点の「その他」メニューに移ります。

アプリバーの内容は `appBar` の設定で指定します。

```ts
appBar: {
  title: "Vitepress Theme Akari Docs",
  version: "v1.0.0",
  socialLinks: [
    { icon: "github", link: "https://github.com/OasisAkari/vitepress-theme-akari-docs", label: "GitHub" },
  ],
},
```

## ドキュメントサーフェスと目次

- 段落とリストの幅は最大で約 760px です。見出し、表、コードブロックはサーフェスの幅いっぱいに広がります。
- 右側の目次にはレベル 2 とレベル 3 の見出しが並びます。読み進めるにつれて現在のセクションがハイライトされ、クリックするとその見出しまでスムーズにスクロールします。
- ウィンドウの幅が 960px より狭いと目次は非表示になり、代わりに右下の目次ボタンで開きます。
- ページのフロントマターに `toc: false` と書くと、そのページには目次がなくなります。

並列ページのグループに属するページでは、サーフェスの上部にタブバーがあります。[サイドナビゲーション](/ja-JP/theme/sidebar#parallel-pages)を参照してください。ヒーローのあるページでは、サーフェスの上部にタイトルと画像が表示されます。[ヒーロー](/ja-JP/theme/hero)を参照してください。

## フローティングアクションボタン

- **トップに戻る**：ページをスクロールすると右下に表示されます。クリックするとページの先頭までスムーズにスクロールし、その間ボタンが広がって「トップに戻る」と表示されます。もう一度クリックするか、自分でスクロールすると止まります。
- **目次**：ウィンドウの幅が 960px より狭いとき、その上に表示されます。クリックすると、現在のページの目次を載せたパネルに展開します。パネルの外側をクリックすると閉じます。

## フッター

ページ送りカードの後に、波線の区切り線とフッターが続きます。左側にロゴ、サイト名、`footer.message`、右側にリンクの列、下部に `footer.copyright` が表示されます。デフォルトでは、リンクの列にはナビゲーションの最初の 4 つのカテゴリが使われます。

## ウィンドウのサイズ

| ウィンドウの幅 | ナビゲーション | 目次 |
| --- | --- | --- |
| 1600px 以上 | レールとナビゲーションドロワーの両方を常に表示 | 右側 |
| 960–1599px | レール。カテゴリにポインターを置くとナビゲーションドロワーがスライドして出る | 右側 |
| 960px 未満 | アプリバーのメニューボタンでナビゲーションドロワーを開く | 右下のボタン |
| 600px 未満 | 上と同じ。ドキュメントサーフェスがウィンドウの端まで広がる | 右下のボタン |

すべてのオプション、CSS 変数、ページの状態は [API](/ja-JP/theme/layout/api) を参照してください。スクロール、タイトルの切り替え、ボタンの折りたたみなどの動作の仕組みは[詳細](/ja-JP/theme/layout/details)を参照してください。
