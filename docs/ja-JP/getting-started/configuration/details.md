# 構成：詳細

## 2 つのレベルの重ね方 {#how-the-two-levels-layer}

`docs/config.ts` と各言語フォルダーの `config.ts` は、VitePress 2 のディレクトリ設定です。

- VitePress は `docs` の中から `config.ts`（または `.mts`、`.js`、`.mjs`）という名前のファイルを探します。`.` で始まるフォルダーはスキップします。各ファイルは、そのフォルダー内のページにだけ適用されます。これはソースファイルの場所で決まり、ページの書き換え後のパスには関係しません。
- ページの設定は複数のレベルを重ねて作られます。上位のレベルから順に、そのページのフォルダーと上位フォルダーの `config.ts`（深いほど優先）、`docs/config.ts`、VitePress のロケール設定、`.vitepress/config.mts` です。
- 重ね合わせはフィールドごとに行われます。オブジェクトでは、各フィールドが値を持つ最上位のレベルから値を取ります。文字列、配列、その他の値は丸ごと置き換えられます。そのため、言語設定の `appBar: { title }` は共通設定の `appBar.socialLinks` を消しません。一方、`socialLinks` 自体は配列なので、丸ごと置き換えることしかできません。
- 重ね合わせはページのレンダリング時に行われ、サーバーでもブラウザーでも同じ結果になります。
- `config.ts` を変更、追加、削除すると、開発サーバーは自動で再起動します。
- カテゴリフォルダーや記事フォルダーにも `config.ts` を置けます。そのフォルダー内のページにだけ適用されるので、たとえば 1 つのカテゴリだけにフッターのメッセージを付けられます。

## フォルダーから生成される言語

`akariContent` は `.vitepress/config.mts` の読み込み時に実行されます。

1. `docs/config.ts` を読み込み、言語フォルダーを見つけます。言語フォルダーは、`docs` 直下のフォルダーのうち `config.ts` を含むものです。ただし `public`、`node_modules`、`.` で始まるフォルダーは除きます。設定ファイルは VitePress と同じ方法で、Vite の設定ローダーによってバンドルされ、実行されます。
2. ルート言語を選びます。ルート言語は `rootLanguage` で指定したフォルダーです。指定がない場合や存在しない場合（このときは通知が出ます）は、アルファベット順で最初のフォルダーを使います。ほかの言語はアルファベット順に続きます。
3. 言語ごとに VitePress の `locales` のエントリーを 1 つ生成します。ルート言語のキーは `root` で、ほかの言語はフォルダー名をキーにします。各エントリーには言語設定の内容が入ります（`head` は除きます。`head` はディレクトリ設定ですでに追加されるため、もう一度追加すると重複します。ロケールの `head` にはその言語のフォントのタグが入ります。[タイポグラフィ](/ja-JP/styles/typography/api#fonts) を参照してください）。`lang` のデフォルトはフォルダー名、`label` のデフォルトは `lang` です。エントリーには生成されたナビゲーション（`themeConfig.akari.sidebar.items`）も入ります。
4. サイトレベルの `lang`、`title`、`description` はルート言語から取ります。

言語設定は、その言語のページに対するディレクトリ設定と、ロケールの両方として働きます。それぞれの役割には目的があります。ロケールは言語メニューにその言語を表示し、コードブロックのコピーボタンなどの Markdown のテキストをその言語でレンダリングし、404 ページなど言語フォルダーの外にあるページにルート言語の設定を与えます。どちらも同じ値を持つので、重ね合わせた結果には影響しません。

言語フォルダーが 1 つもない場合、`akariContent` はロケールも書き換えも生成しません。サイトは `.vitepress/config.mts` の設定で動作し、ナビゲーションは手書きの `sidebar.items` か、VitePress の `themeConfig.sidebar` から作られます。

## パスとナビゲーション

`akariContent` は VitePress の `rewrites` 関数も返し、各言語の Markdown のフロントマターを読み込んでナビゲーションを生成します。詳しいルールは [ページの作成：詳細](/ja-JP/getting-started/writing/details) を参照してください。言語設定または共通設定で `sidebar.items` を設定している言語では、手書きのナビゲーションを使い、ナビゲーションは生成されません。

## 開発中の更新

| 変更 | 結果 |
| --- | --- |
| `config.ts` を追加、削除、編集する | VitePress が開発サーバーを再起動し、`akariContent` が再実行されます |
| Markdown を追加、削除する、またはフロントマターを編集する | `content.plugin` が約 120ms 後にナビゲーションを再生成します。ナビゲーションが変わった場合は、サイトデータを更新してページを再読み込みします |
| 本文だけを編集する | ナビゲーションは変わりません。VitePress が独自のホットアップデートで処理し、ページは再読み込みされません |

`content.plugin` が監視するのは、言語フォルダー内の `.md` ファイルだけです。サーバーの実行中に言語フォルダーを丸ごと移動した場合、プラグインは次に再起動するまでそのフォルダーをスキップします。

## 設定ファイルに書けるもの

設定ファイルは Node.js で実行され、その結果はシリアライズされてサイトデータとともにブラウザーに送られます。そのため、設定ファイルはデータにしか向きません。Vue コンポーネントなど、インポートに依存するオブジェクトは渡せません。コンポーネントを置き換えるには、テーマのエントリーで `provideAkariComponents` を呼び出します。[テーマの拡張](/ja-JP/theme/extending/api#provideakaricomponents) を参照してください。

## defineAkariConfig のインポート

`defineAkariConfig` は `theme/define.ts` にあります。このファイルは型だけをインポートし、拡張子（`./types.ts`）まで明記しています。設定ファイルも、完全なファイル名（`define.ts`）でこれをインポートします。Vite は設定ファイルを読み込むとき、拡張子のないインポートなど、将来のネイティブローダーで扱えないパターンに警告を出します。このように書いた設定ファイルでは警告は出ません。そのために `tsconfig.json` で `allowImportingTsExtensions` を有効にしています。

ビルドでは、同じ種類の警告がまだ 1 つ表示されます。これは `.vitepress/config.mts` 自身のインポートによるもので、ビルド結果には影響しません。
