# 검색: 세부 사항

## 컨테이너 변환 {#container-transform}

검색 패널은 네이티브 모달 `<dialog>`입니다. Web Animations API로 구현한 M3 컨테이너 변환으로 펼쳐집니다. 언어 선택기와 설정 대화상자도 같은 구현(`useContainerTransform`)을 씁니다.

- 애니메이션되는 것은 언제나 실제 패널이며, 첫 프레임부터 최종 크기로 배치되어 있습니다. 시작 시점에는 버튼 모양의 창(`clip-path` 캡슐)이 패널 자체 검색 바의 시작 부분만 보여 주고, 평행 이동으로 그 창을 버튼 위에 놓습니다. 따라서 첫 프레임은 여전히 “아이콘 + 자리표시자” 검색 상자처럼 보입니다.
- 펼쳐지면서 평행 이동은 0으로 돌아가고, 창은 패널 전체(그림자 포함)로 커집니다. 콘텐츠는 단계적으로 드러나고, 결과 영역과 닫기 버튼이 함께 페이드 인하며, 중간에 빈 표면이 나타나지 않습니다. 애니메이션의 최종 상태가 패널의 평소 스타일이므로, 애니메이션을 제거해도 튀는 현상이 없습니다.
- 버튼의 픽셀 복사본이 창 위에 놓여 함께 움직입니다. 버튼과 패널의 콘텐츠는 크로스페이드하지 않고, 한쪽이 페이드 아웃한 뒤 다른 쪽이 페이드 인합니다(M3 fade through). 열 때는 먼저 패널 표면이 복사본 아래에서 페이드 인하고, 이어서 복사본이 페이드 아웃한 다음, 패널 자체의 검색 바가 페이드 인합니다. 크기가 다른 두 텍스트가 동시에 보이는 일은 없습니다.
- 닫을 때는 왔던 길로 돌아갑니다. 결과 영역과 검색 바가 먼저 페이드 아웃하고, 중간에 버튼 복사본이 페이드 인하여 이어받은 다음, 그 아래에서 패널 표면이 페이드 아웃합니다. 버튼으로 돌아가는 마지막 구간에서는 표현형 모션의 바운스를 포함해 보이는 것이 버튼 자체이며, 실제 버튼과 정확히 같은 모습으로 끝납니다. 따라서 배경이 없는 버튼(톱니바퀴 버튼 등)도 마지막에 배경 조각이 번쩍이지 않습니다. 열거나 닫는 도중에 중단되면 현재 프레임에서 모션이 거꾸로 진행됩니다.
- 창의 크기와 모서리 반경은 버튼의 현재 위치와 크기에서 가져옵니다. 패널의 위치는 애니메이션이 시작될 때 다시 측정되며, 고정 좌표에 의존하는 부분은 없습니다.

| 모션 | 펼치기 | 접기 |
| --- | --- | --- |
| 표준 | 약 300ms, `cubic-bezier(0.2, 0, 0, 1)` | 약 250ms, 바운스 없음 |
| 표현형 | 약 500ms, `cubic-bezier(0.38, 1.21, 0.22, 1)`, 살짝 넘쳤다가 자리 잡음 | 약 400ms, 같은 곡선, 접힐 때 살짝 바운스 |

시스템의 “동작 줄이기” 설정이 켜져 있으면 패널은 애니메이션 없이 열리고 닫힙니다. 네이티브 대화상자가 최상위 레이어 표시, 비활성 배경, `Esc`로 닫기를 제공합니다. 열면 포커스가 입력란으로 이동하고, 닫으면 열기 전에 있던 곳으로 돌아가며, 그 요소를 더 이상 쓸 수 없으면 검색 버튼으로 돌아갑니다.

## 색인 빌드

- Vite 플러그인은 개발 서버가 시작될 때와 빌드가 시작될 때 `docs`의 모든 `.md` 파일(`.vitepress`, `public`, `.`으로 시작하는 디렉터리 제외)을 스캔하여 `docs/public/search-index.json`을 씁니다. 개발 중에는 Markdown 파일이 추가, 변경, 삭제되고 약 150ms 후에 색인을 다시 생성합니다. 빌드가 끝나면 파일을 출력 루트로 복사합니다.
- 페이지 URL은 `content.route`로 계산되므로 페이지의 실제 URL과 일치합니다.
- 페이지 제목은 프런트매터 `title`, 그다음 첫 번째 1단계 제목, 그다음 파일 이름 순으로 정해집니다.
- 2단계와 3단계 제목마다 섹션 항목이 하나씩 생깁니다. 그 앵커는 VitePress가 생성하는 제목 id와 일치합니다.
- 펜스 코드 블록은 색인에서 제외됩니다. HTML 태그, 링크 URL, Markdown 마크업은 제거되고 텍스트만 남습니다. 각 항목의 본문 텍스트는 최대 4000자입니다.

## 매칭과 순위

검색어는 먼저 정규화(대소문자, 전각·반각 형태 등)된 뒤 공백을 기준으로 단어로 나뉩니다. 항목은 모든 단어가 제목, 페이지 제목, 본문 텍스트 중 어딘가에 나타날 때만 일치합니다. 점수는 다음과 같이 합산되며, 여기서 “제목”은 항목 자신의 제목으로, 페이지 항목은 페이지 제목, 섹션 항목은 섹션 제목입니다.

| 조건 | 점수 |
| --- | --- |
| 제목이 검색어 전체와 정확히 같음 | +100 |
| 제목이 검색어 전체로 시작함 | +60 |
| 제목에 검색어 전체가 포함됨 | +40 |
| 페이지 제목에 검색어 전체가 포함됨 | +20 |
| 본문 텍스트에 검색어 전체가 포함됨 | +10 |
| 단어마다: 제목 / 페이지 제목 / 본문 텍스트에 있음 | +24 / +10 / +6 |
| 항목 수준: 페이지 / 2단계 제목 / 3단계 제목 | +3 / +2 / +1 |

결과는 점수가 높은 순으로 정렬되며, 점수가 같으면 제목순으로 정렬됩니다. URL마다 결과는 하나만 남고, 최대 `maxResults`개를 반환합니다. 다국어 사이트에서는 로컬 색인이 모든 언어의 페이지를 담고 있으며, 현재 언어의 경로 아래에 있는 항목만 남깁니다(루트 언어에는 `/<language folder>/` 아래의 페이지가 포함되지 않습니다).

## 로딩과 캐시

- 로컬 색인은 처음 검색할 때 로드되고, 이후 페이지 안에 캐시됩니다. 개발 모드에서는 브라우저 캐시를 쓰지 않으므로 수정한 내용을 바로 검색할 수 있습니다.
- 입력은 `debounce`만큼 디바운스됩니다. 새 검색어를 입력하거나 패널을 닫으면 진행 중인 요청이 `AbortSignal`로 중단됩니다.
- 색인 파일이 없거나 형식이 잘못되었으면 패널에 오류와 다시 시도 버튼이 표시됩니다.

## 패널 상태

| 상태 | 표시 내용 |
| --- | --- |
| 빈 입력 | 검색 힌트와 단축키 도움말 |
| 로딩 중 | M3 로딩 인디케이터 |
| 결과 | 페이지 제목, 섹션 제목, 발췌문, 강조된 일치 부분. 현재 항목에는 `secondary-container` 배경이 있습니다 |
| 결과 없음 | 다른 키워드를 시도해 보라는 제안 |
| 실패 | 오류 원인과 다시 시도 버튼 |

결과를 열면 VitePress 라우터를 거치므로 SPA 내비게이션이 유지됩니다. 입력란, 결과 목록, 오류 메시지에는 각각 ARIA 이름이 있습니다. 앱 바의 단축키 힌트는 `label-small` 글자 스타일과 완전히 둥근 키캡을 쓰고, 패널의 화살표 키, `Enter`, `Esc` 힌트는 `shape-extra-small` 모서리를 씁니다.

## 알려진 제한 사항

- 로컬 색인은 단순한 부분 문자열 매칭을 쓰며, 맞춤법 교정이나 의미 검색은 없습니다. 필요하면 HTTP 백엔드나 등록된 백엔드를 쓰세요.
- 로컬 색인은 개발 서버가 실행 중이거나 빌드하는 동안에만 갱신됩니다. 개발 서버가 실행되지 않을 때 수정한 Markdown은 다음 `npm run dev` 또는 `npm run build` 후에 검색할 수 있습니다.
