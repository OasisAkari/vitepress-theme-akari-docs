# 撰写页面：技术细节

## 地址规则

VitePress 用 `akariContent` 生成的 `rewrites` 函数决定每个页面在哪里提供：

| 源文件 | 提供为 | 地址 |
| --- | --- | --- |
| `zh-CN/index.md` | `index.md` | `/` |
| `zh-CN/theme/layout/index.md` | `theme/layout.md` | `/theme/layout` |
| `zh-CN/styles/icons/using.md` | `styles/icons/using.md` | `/styles/icons/using` |
| `en-US/index.md` | `en-US/index.md` | `/en-US/` |
| `en-US/theme/i18n/index.md` | `en-US/theme/i18n.md` | `/en-US/theme/i18n` |
| `404.md`（语言文件夹之外） | 不变 | 不变 |

- 根语言的文件夹名从路径中去掉，其他语言保留文件夹名作为前缀。
- 恰好位于「语言/分类/文章/index.md」的文件改写为「分类/文章.md」，文章因此以文件夹名为地址，末尾没有斜杠。其他文件只去掉根语言的文件夹名。
- 开启了 `cleanUrls`，构建产物中 `/theme/layout` 对应 `theme/layout.html`。

## 相对路径

- **链接**：VitePress 把 Markdown 链接原样输出，由浏览器按页面地址解析。文章的地址是 `/theme/layout` 而不是 `/theme/layout/`，所以其中的 `./sidebar` 指向 `/theme/sidebar`，而不是文章文件夹中的文件。站内链接因此要写完整的地址。
- **图片与资源**：图片由 Vite 当作模块导入，按源文件所在的位置解析，所以 `./图片.png` 指向文章文件夹中的文件。小图片会被内联为 data URL，其余在构建时加上哈希复制到产物中。

## 导航怎样生成

每种语言的导航由它的语言文件夹生成，规则如下：

- **分类**：语言文件夹中的每个目录是一个分类。顺序取共用配置中 `sidebar.categories` 的键序，接着是只在语言配置中出现的键，最后是没有写进 `categories` 的目录，按名称排序。没有文章的分类不显示。分类的名称取 `text`，没有时显示目录名。
- **文章**：分类目录中每个带 `index.md` 的文件夹。名称取头部信息的 `title`，其次是第一个一级标题，再次是文件夹名。排序先比较 `order`，没有 `order` 的排在最后，相同时按文件夹名排序。
- **首页**：语言文件夹的 `index.md` 默认不进导航。写了 `category` 时它加入该分类；没有 `order` 时排在分类的最前面。
- **平行页面**：`parallel` 中的每一项按顺序生成一个标签，文章自己是第一个标签。这一项在导航中没有自己的链接，由第一个标签代表；平行页面不单独出现在导航中。
- **一级标题的识别**：跳过围栏代码块，取第一个以 `# ` 开头的行，去掉其中的 Markdown 标记。

生成的导航与手写的 `sidebar.items` 结构相同（`AkariSidebarItem`），所以展开、高亮、翻页与页尾链接分栏的行为完全一样。

## 提示

生成导航时，以下情况会在终端给出提示，同一条提示只出现一次：

- `parallel` 列出的文件不存在，或者不是文章文件夹中的文件名（例如写了路径）。这一项被跳过。
- 页面不在导航结构中：直接放在分类目录中的 `.md`、更深层的文件、没有被任何文章列为平行页面的文件。它们仍然会生成页面，只是不出现在导航中。
- `rootLanguage` 指定的文件夹不是语言文件夹。

## 对应页面

切换语言时，主题把当前地址换到目标语言下（`/theme/i18n` ↔ `/en-US/theme/i18n`），如果目标语言的导航中有这个地址就打开它，否则打开目标语言的首页。所以切换语言能停留在同一页的条件是：两个页面在各自语言文件夹中的路径相同，并且目标页面在目标语言的导航中。

## 搜索索引

本地搜索的索引由 VitePress 生成，链接就是页面实际的地址（按上面的规则改写之后的）。每种语言一个索引；每个页面按标题切成章节，一级标题下的部分代表页面本身，平行页面也各自成页。
