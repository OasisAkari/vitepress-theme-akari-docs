# كتابة الصفحات: API

## البيانات الأمامية {#frontmatter}

| الحقل | النوع | يُستخدم في | الوصف |
| --- | --- | --- | --- |
| `title` | `string` | كل الصفحات | عنوان الصفحة، وهو أيضًا اسم المقالة في التنقل. القيمة الافتراضية هي أول عنوان من المستوى الأول (h1)، ثم اسم المجلد |
| `description` | `string` | كل الصفحات | وصف الصفحة، يُكتب في `<meta name="description">`؛ وهو أيضًا الملخص الافتراضي لقسم الواجهة (hero) |
| `icon` | `string` | المقالات | أيقونة عنصر التنقل؛ يجب أن تكون أيقونة مسجّلة |
| `badge` | `string` | المقالات | شارة عنصر التنقل، مثل `New` |
| `order` | `number` | المقالات | الموضع داخل الفئة، الأصغر أولًا. المقالات التي ليس لها `order` تأتي بعدها، مرتبة حسب اسم المجلد |
| `parallel` | `string[]` | المقالات | الصفحات المتوازية: أسماء ملفات `.md` الأخرى في المجلد نفسه (يمكن حذف `.md`)، وتوضع بعد المقالة بترتيب شريط التبويب |
| `tab` | `string` | المقالات والصفحات المتوازية | العنوان في شريط التبويب؛ والقيمة الافتراضية هي عنوان الصفحة |
| `category` | `string` | الصفحة الرئيسية للغة | لا تكون الصفحة الرئيسية في التنقل افتراضيًا. امنحها اسم مجلد فئة فتنضم إلى تلك الفئة، وتكون أولها ما لم يكن لها `order` |
| `hero` | `string \| object` | كل الصفحات | قسم الواجهة في أعلى الصفحة؛ لحقوله راجع [قسم الواجهة](/ar-SA/theme/hero/api) |
| `toc` | `boolean` | كل الصفحات | مع `false` يُخفى جدول المحتويات على اليسار وزر جدول المحتويات في الشاشات الضيقة |

المقالة هي ملف `index.md` لمجلد داخل مجلد فئة. وتعمل حقول البيانات الأمامية (frontmatter) الخاصة بـ VitePress نفسه (مثل `head` و`titleTemplate`) كالمعتاد.

```yaml
---
title: الأيقونات
description: أيقونات Material Symbols التي تستخدمها السمة
icon: interests
order: 2
badge: New
tab: نظرة عامة
parallel:
  - choosing
  - using
hero:
  image: /hero/icons-hero.svg
  fit: contain
---
```

## الجداول

صيغة الأنابيب القياسية. عند تفعيل `akariMarkdown`، يُغلَّف كل جدول في حاوية ذات حدّ خارجي بأسلوب M3، والجدول العريض جدًا يُمرَّر أفقيًا داخل الحد.

```md
| الحقل | الوصف |
| --- | --- |
| `title` | عنوان الصفحة |
```

جدول `<table>` المكتوب مباشرة بـ HTML ليست له حاوية خارجية. أما الجدول نفسه فتنسيقه هو نفسه.

## الصور {#images}

```md
![الوصف](./image.png)
![الوصف](/hero/image.svg)
![الوصف](https://example.com/image.png)
```

عند عرض الصفحة، تحصل كل صورة Markdown على `width` و`height` خاصين بها. تحجز الصفحة مساحة الصورة قبل تحميلها، فلا يهتز شيء بعد تحميلها. وتبقى الصور قابلة للتحجيم بـ `max-width: 100%` مع الحفاظ على نسبة أبعادها.

| الصورة | تقيسها |
| --- | --- |
| في مجلد المقالة (`./image.png`) | VitePress، الذي يقرأ الصورة المجاورة للملف المصدري |
| في `docs/public` (`/hero/image.svg`) | VitePress |
| بعيدة (`https://…`) | [markdown-it-image-size](https://github.com/boyum/markdown-it-image-size)، التي تضيفها السمة: تنزّل الصورة عند عرض الصفحة لقراءة حجمها، وتخزّنها مؤقتًا حسب عنوان URL لمدة أسبوع (`node_modules/markdown-it-image-size/.cache`) |

- الصورة المحلية التي لها `width` فقط أو `height` فقط تُكمَل قيمتها الأخرى بالتناسب. والصورة التي لها القيمتان تُترك كما هي.
- عندما يفشل تنزيل صورة بعيدة (عدم الاتصال، عنوان URL خاطئ)، تُظهر الطرفية تنبيهًا، ولا تحصل الصورة على عرض أو ارتفاع، وتُولَّد الصفحة كالمعتاد. التنزيل متزامن، لذا يتوقف خادم التطوير برهة عند عرض صفحة فيها صورة بعيدة جديدة؛ وبعد ذلك تجيب الذاكرة المؤقتة مباشرة.
- عنصر `<img>` المكتوب مباشرة بـ HTML لا يُقاس. اكتب عرضه وارتفاعه بنفسك.
- يمكنك إيقاف قياس الصور البعيدة، أو ضبط ذاكرتها المؤقتة، في `.vitepress/config.mts`؛ راجع [التهيئة](/ar-SA/getting-started/configuration/api#akarimarkdown).

## الروابط

للروابط في المتن أيقونة أمامها بحجم النص نفسه: `link` للروابط الداخلية، و`open_in_new` للروابط التي تُفتح في علامة تبويب جديدة (`target="_blank"`، ومنها الروابط الخارجية). أما هذه الروابط فليست لها أيقونة: مراسي العناوين، والروابط التي تغلّف صورة، وعلامات الحواشي، والروابط الموضوعة في منفذ مكون (لها الخاصية `slot`).

## الحاويات المخصصة والشيفرة

للحاويات المخصصة ومجموعات الشيفرة في VitePress كلها أنماط مطابقة في السمة:

````md
::: tip تلميح
ملاحظة اختيارية.
:::

::: warning
أمر يجب الانتباه إليه.
:::

::: code-group

```bash [npm]
npm install
```

```bash [pnpm]
pnpm install
```

:::
````

الحاويات المخصصة هي `info` و`tip` و`warning` و`danger` و`details`. وكتلة الشيفرة التي تحدد لغة تحصل على تلوين الصيغة وزر نسخ. ويأتي نص زر النسخ من `markdown.codeCopyButton` في تهيئة اللغة.

## الأصناف المساعدة للعروض التوضيحية

| الصنف | الغرض |
| --- | --- |
| `demo-surface` | منطقة عرض توضيحي بحدّ خارجي وخلفية `surface-container-low`، ونصف قطر زوايا 16px وحشوة |
| `demo-row` | صف أفقي يلتف، بفجوة 12px |
| `demo-grid` | شبكة بطاقات، كل عمود 240px على الأقل، وعمود واحد في الشاشات الضيقة |
| `demo-stack` | تكديس عمودي، بفجوة 16px |

```html
<div class="demo-surface">
  <div class="demo-row">
    <m3e-button variant="filled">موافق</m3e-button>
    <m3e-button variant="outlined">إلغاء</m3e-button>
  </div>
</div>
```

## مكونات m3e

يمكنك كتابة مكونات m3e المسجّلة مباشرة في Markdown. تسجّل السمة هذه المكونات في `docs/.vitepress/theme/m3e.ts`:

`app-bar`، `badge`، `button`، `card`، `checkbox`، `chips`، `content-pane`، `dialog`، `divider`، `drawer-container`، `heading`، `icon`، `icon-button`، `list`، `loading-indicator`، `menu`، `nav-bar`، `nav-menu`، `nav-rail`، `search`، `segmented-button`، `snackbar`، `switch`، `tabs`، `theme`، `tooltip`.

لاستخدام مكون آخر، استورد مساره الفرعي في `m3e.ts`، مثل `import "@m3e/web/slider";`.

- للعنوان داخل مكون، استخدم `<m3e-heading>`. ومع الخاصية `m3e-toc-ignore` يبقى خارج جدول المحتويات.
- اكتب الأيقونة هكذا `<m3e-icon name="search"></m3e-icon>`. يجب تسجيل الأيقونة في `icons.ts` أولًا؛ راجع [استخدام الأيقونات](/ar-SA/styles/icons/using).
